Show the user the passage, which suits any entry file, and agree with them where it goes: an entry file that every
session of their agents loads. If a passage there already says all of it, map that one instead. If a member listed
in members_in_entry_files already says it, the passage is placed and mapped: go on to next_action. This tool writes
none of the project's guidance.

The first member need not be the passage: it can be any file or setting in the project that keeps the principles
in front of the agent, such as a timer of the project's own, or the committed setting that enables the plugin for
the team, its enabledPlugins line. This helps teammates only if they can install the plugin from a marketplace
they can access. Map it with a role that names, as STEP, the step it runs and, as TRIGGER, what
starts that step: a hook, a timer or a reader. Mapping it says only that the project names something to keep them
held; this principle's audit judges whether it does.

To map such a place: %{any_place}

Where the owner enables the plugin only at user scope, the project has nothing to map for it. Say so, and name the
two ways on: commit the project-scope enablement and map its line, or leave principles not set up for now.

Where only a reader enforces a step, with no hook or timer that runs it, say so in a sentence of its own after
the passage.

Where the project says how a teammate gets `principles`, such as an install section or a setup note, link to it in
a sentence of its own after the passage. Say in a few words what `principles` is, so a teammate knows what the
passage and any link lead to. Where the project says nowhere how to get it, tell the user that a teammate who reads
the passage cannot act on it without that.

Where a passage the project already has carries one of the proposed passage's steps, leave that step out and map
that passage too, so each rule is said once, giving its file as PATH and its heading as HEADING: %{existing}

Place the passage exactly as printed, adding nothing to it and changing none of its words. Anything else you
say goes in a sentence of its own after it, which the user agrees to with the passage.

Once the passage is in the file, map it: %{command}

That command names the heading the passage is proposed under; where you placed it under another heading, give
--section the heading you placed it under.
