Points MEMBER of principle ID at a new place, keeping its role and the key its audit is filed under. Use it when a
heading was renamed, a passage's anchor was lost, or the member should be narrower or wider, as when a passage was
cut short. When the member's file was renamed or moved, or its text moved into another file, give that path with
`--path PATH`, with the member's own `--section`, passage or `--query` flags, so it keeps its last audit. This tool
does not guess the new path: find it with git or by reading the project. The location flags are as for `add-member`
and replace the old ones whole, so `--path` alone makes the member the whole file. MEMBER is the id `show-principle`
lists. The result says which lines the member now spans.

A new literal `--ending-at` must occur once after the complete opening in the selected region; overlapping matches count.
`ambiguous_passage_end` refuses before writing: exact `eligible_ending_count`, up to five `ending_candidates` with
1-based line/character columns, and `ending_candidates_omitted`. Quote more specific closing text.
Existing stored members and evidence keep the first ending and their hashes; only new add/move is stricter.

An id no member has is refused with `unknown_member`. When it differs from one mapped id only in case, spacing,
dashes or quotes, the refusal names that id under `did_you_mean` and starts its repair with this command run on it
instead. This tool never acts on the near miss: check that it is the member you meant before you run it.
