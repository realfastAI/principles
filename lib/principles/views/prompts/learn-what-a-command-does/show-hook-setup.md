Use it to give a project the reports the principles plugin's hooks give, when this tool is installed as a gem
without the plugin: at each session's start, what the agent should act on, and after each shell call that commits,
the mapped members the commit changed. Without them, a changed member goes unseen until someone runs
`list-member-problems`.

It writes nothing. First, when the `principles` on PATH is not this copy, `principles_on_path` says so: none there
prints its version, so every entry would print its failure line, or another version is first, which the entries would
run instead; show it to the user before the entries. It prints, under `hosts`, Claude Code's entries first, for its
gitignored `.claude/settings.local.json`, then Codex's, for `.codex/hooks.json`, each with the `file` they go in, why
the block is `offered`, and the `entries` to merge into its `hooks`. Each entry runs `principles` as found on PATH,
so an upgrade leaves it unchanged, and echoes that principles failed to start when it cannot run, instead of failing
the hook. `next_action` says to write them only once the user agrees, and how to remove them: delete the entries
whose command starts `principles report-`, as when the plugin is enabled, since the reports would come twice.
